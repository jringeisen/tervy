## Findings that changed implementation

- 🧪 Codex emits `agent-turn-complete` for an internal title-generation conversation, using that conversation's ID. Accepting its first notify produced an unusable fork ID. ✅ The documented `tui.terminal_title` setting supports a thread-ID item in the exact-version CLI source. DevDesk requests `session-id`, then accepts a full notify ID only when it matches the public OSC title's validated UUID prefix. Titles truncate the UUID to 29 characters plus dots in this version; no ID is manufactured from the prefix. Unknown identity stays unavailable until a matching notify or the public exit summary. User changes to title settings can reduce status fidelity. No transcript or rollout content is read.
- 🧪 Quotes in override key paths are literal in 0.162.0. `mcp_servers."fixture-write".enabled=false` creates a different invalid server. Use unquoted ordinary names; reject unusual names that cannot be addressed exactly. Config read/parse errors fail closed without echoing values. Read user, selected profile, system and project ancestor layers, with size/count limits. This machine's user config has **herd** and **laravel-boost**; `/etc/codex/config.toml` is absent. Tests use local substitutes, never those real services.
- 🧪 Disabling configured servers and plugins still exposed built-in `mcp__codex_worktrees__` tools. Side also disables `worktrees`, `workspace_dependencies`, lifecycle hooks, automatic skill MCP installation and tool suggestions; `agents.enabled=false` removes collaboration. Final fork reports contain no MCP or collaboration tools. ❓ Registry absence is a model report, not an independent registry API; actual configured-server startup is checked separately.
- 🧪 `--no-daemon` confines the TUI, but normal command workers create new SIDs. TERM/KILL of only the original SID left the deterministic workload running. Legacy execution and native Ctrl-C prototypes did not fix this reliably and were removed. Before Stop, Core discovers live descendants through kernel parent/birth identities, journals their separate sessions, retains them through reparenting and sweeps each until empty. Recovery also discovers Codex descendants before terminating a surviving TUI. Other providers retain their existing session scope. The user's shared daemon is never stopped.

❓ A detached job which escapes or loses its parent before discovery cannot be reconstructed from kernel ancestry. M7 must harden crash coverage; this is not a guarantee that every daemonised or already-reparented process is recoverable. CLI version changes require rerunning the contracts before relying on these flags.
